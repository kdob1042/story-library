# 漫画構成フェーズ

原稿理解を保った同じAIが設計する。別エージェント、専用モデル、外部APIへの委任を必須にしない。

`workGoal → beat → panel → page` の順で、読者に何を理解・期待してほしいかを決める。beatの役割はsetup/reveal/reaction/action/pause/payoff/transitionなど。sceneとpageの境界は別物である。

各コマでは、見せる瞬間、原稿との対応、人物ID、ショット意図、視線／動作方向、重要物、掲載する台詞／心情／ナレーションを区別する。地の文の保持と地の文の全量印字は別であり、絵で表す描写を機械的にcaptionへ流さない。画像に吹き出しを焼き込む指示ではなく、文字層を分ける。

ページはコマ数を固定しない。全面1コマ、大コマ＋小さな反応、横長／縦長、静かな間を目的に応じて使う。全ページの引き、一定比率の大ゴマ、派手な斜め枠をノルマにしない。縦スクロールでは次ページが同時に見える可能性を考慮し、紙のページめくり効果を保証しない。

構造は共有name-plan/v2が定めるrow/column/leafと相対比率・順序で表す。単に「大ゴマ60%」だけではなく上下左右・隣接関係まで示す。生のpointsや座標をAIが手計算してcompilerの代用品にしない。既存手修正と固定は保護し、変更が必要な範囲を明示する。

演出手段の確認カード（使わない判断も可）:

| 手段 | 適用する条件 | 避ける条件 |
|---|---|---|
| 無言の反応 | 原文に反応があり、受け止める時間が必要 | 原文にない気持ち／行動を既成事実にする |
| 開示を遅らせる | 情報の順番が読者の期待を作る | 因果・時系列を壊す、前ページで既に見せる |
| 大小の対比 | 注目すべき瞬間と補助情報に差がある | 大ゴマの割当数を満たすだけ |
| 動作の分解 | 重要な選択・動作過程を読ませたい | 冗長な同一ショットの水増し |
| 静かな着地 | 感情を余韻として残したい | 毎ページに煽りを要求する |

出力は共有schemaを参照する。ここに独自のJSON schemaや作品別のコード分岐を増やさない。
