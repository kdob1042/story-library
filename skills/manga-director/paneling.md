# 漫画構成

`workGoal → beat → panel → page` の順に、読者に何を理解・期待してほしいかを決める。beatの役割はsetup/reveal/reaction/action/pause/payoff/transitionなど。sceneとpageの境界は分ける。

各コマは、見せる瞬間、原稿対応、人物ID、ショット意図、視線／動作方向、重要物、掲載する台詞・心情・ナレーションを示す。絵で表す地の文を全量captionにせず、文字層を画像から分ける。

ページのコマ数は目的に合わせる。全面1コマ、大小の対比、横長／縦長、静かな間を使い分け、引き・大ゴマ比率・斜め枠をノルマにしない。縦スクロールでは紙のページめくり効果を前提にしない。

共有name-plan/v2のrow/column/leafで、順序・相対比率・上下左右の隣接関係を表す。AIは意味構造、compilerは座標を担当する。生のpointsを手計算せず、独自schemaや作品別コードを追加しない。既存の手修正と固定を保護し、変更範囲を明示する。

| 演出 | 使う条件 | 避けること |
| --- | --- | --- |
| 無言の反応 | 原文に反応があり、受け止める間が必要 | 原文にない気持ち・行動の追加 |
| 開示を遅らせる | 情報順が期待を作る | 因果・時系列の破壊、既出情報の隠し直し |
| 大小の対比 | 主役の瞬間と補助情報を分ける | 大ゴマ数だけを満たす |
| 動作の分解 | 選択・動作過程を読ませる | 同一ショットの水増し |
| 静かな着地 | 感情の余韻を残す | 毎ページの煽り |

演出を使わない判断も認める。
