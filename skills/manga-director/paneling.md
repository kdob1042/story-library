# 漫画構成

`workGoal → beat → panel → page` の順に、読者に何を理解・期待してほしいかを決める。beatの役割はsetup/reveal/reaction/action/pause/payoff/transitionなど。sceneとpageの境界は分ける。

各コマは、見せる瞬間、原稿対応、人物ID、ショット意図、視線／動作方向、重要物、掲載する台詞・心情・ナレーションを示す。絵で表す地の文を全量captionにせず、文字層を画像から分ける。

ページのコマ数は目的に合わせる。全面1コマ、大小の対比、横長／縦長、静かな間を使い分け、引き・大ゴマ比率・斜め枠をノルマにしない。縦スクロールでは紙のページめくり効果を前提にしない。

構成draftは既存compilerが受け取るrow/column/leafで、順序・相対比率・上下左右の隣接関係を表す。AIは意味構造、compilerは座標を担当し、保存は[handoff.md](handoff.md)のページ単位name-plan/v3へ書き出す。生のpointsを手計算せず、独自schemaや作品別コードを追加しない。既存の手修正と固定を保護し、変更範囲を明示する。

| 演出 | 使う条件 | 避けること |
| --- | --- | --- |
| 無言の反応 | 原文に反応があり、受け止める間が必要 | 原文にない気持ち・行動の追加 |
| 開示を遅らせる | 情報順が期待を作る | 因果・時系列の破壊、既出情報の隠し直し |
| 大小の対比 | 主役の瞬間と補助情報を分ける | 大ゴマ数だけを満たす |
| 動作の分解 | 選択・動作過程を読ませる | 同一ショットの水増し |
| 静かな着地 | 感情の余韻を残す | 毎ページの煽り |

演出を使わない判断も認める。

## 感情の滞在と緩急

情報の順番だけでなく、読者が受け止める時間を設計する。重要な節目では原稿にある出来事・反応・持続・次の動作を見分け、一枚にまとめると時間が失われる箇所を分ける。この並びを全場面の固定テンプレートにしない。

追加・分割するコマには「何に留まるか」「対応原文」「前後との違い」「削ると失われる読者体験」を短く記す。既存の意図欄や制作メモを使い、共有契約に独自フィールドを足さない。新情報がなくても持続・距離・応答を読む役割があれば残す。同じ感情を言い換えるだけなら統合を検討し、原稿の出来事自体の削除はscript_changeに分ける。

原稿の拍手・視線・沈黙・手元などを使う。無言であること自体を余韻と判定しない。涙・ためらい・意味深な接触・新しい回想など、原文にない反応を足す場合はscript_changeへ分ける。

反応を受け止める前に次の情報を入れていないか確かめ、反応の独立、大きく留める構図、文字量の調整、ページ分割などから必要な手段だけ選ぶ。大ゴマ数・無言率・ページ数をノルマにしない。

増ページ可なら圧縮維持より感情の着地を優先し、必要な増分と理由を示す。制約がある場合もまず周辺の重複を整理し、重要な反応を真っ先に削らない。会話・笑い・競技を一律に遅くせず、余韻の前後に速さの差と次へ進む力を残す。ページ終端に煽りや新情報を必須にしない。

## 漫画としての見栄えと絵の変化

ページ全体と連続するページを見渡し、主対象・寄り引き・角度・人物配置・動き・背景・明暗・コマの大小が似た画面ばかりになっていないかを点検する。台詞や場面の役割が違っても、見た目が続けば単調になりうる。注目させたい瞬間に合わせて変化と対比をつくり、漫画として見て楽しいか、見せ場が映えるかを確かめる。画角変更の回数をノルマにせず、視線の流れや空間の分かりやすさを保つ。

たとえば写真で先輩を探す場面と部名の丸をなぞる場面が、どちらも冊子のアップなら、文字の内容を替えるだけでは絵の変化が乏しい。前者は冊子を見る顔や視線も含め、後者はペン先と既存の線を寄って見せるなど、原文にある動作を異なる画面として設計する。すでにある丸を「初めて決意した瞬間」に変えるなど、見栄えのために事実を創作しない。

同じ構図で時間の持続・対比・回収を読ませる判断も認める。その場合は実際に絵の連なりとして効果が出るかを確認し、役割の違いを言葉で説明できるだけで合格にしない。脚本の興味や流れは、絵の単調さとは別に[review.md](review.md)で点検する。

## 作画の継続状態

保存するv3では、場所・時刻・小道具・位置関係・必須条件を話の共通 `scenes` に、衣装を各sceneの `appearances` に置く。コマは `sceneId`、登場人物の `characterId` と `appearanceId` で参照し、そのコマ固有の `visualState`・`emotion`・`holding` を必要な分だけ記す。本文・確定設定にない事実や台詞を創作しない。場面転換・衣装変更・時間経過をまたいで古い状態を引き継がない。文字は画像に描かせず、本文は既存の掲載方針で保持する。

旧v2や構成draftの `panel.continuity` は互換入力であり、v3の保存先ではない。変換時には共通sceneの場所等が自動で引き継がれると仮定せず、書出し後のscene／appearance参照と値を確認する。同じ場面の既出コマを根拠にするときだけ `previousPanelId` を指定し、画像参照への利用可否はアプリの実装で確認する。アプリと契約の対応版が揃う前は機械取込可能と報告しない。

アプリで人が衣装・見た目・感情・持ち物・参照コマを明示固定した場合、その値を次の作画でネーム由来の状態より優先する。Directorは再取込時に人の固定値を推測で上書きしない。固定解除はアプリ上の明示操作とする。continuity QAは採用済み画像を比べた指摘だけを返し、ネーム・作画を自動変更しない。
